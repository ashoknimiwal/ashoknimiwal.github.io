ThemeScope

Prototype Private repo

An LLM-powered research system that scores companies on structural themes from their own disclosures — where every score is traceable to the sentence that produced it.

Two of the largest risks in a modern portfolio never appear on a balance sheet: how structurally exposed a company is to an economy-wide shift like AI, and whether you can trust how its management talks about it. Both are sitting in plain sight in earnings calls and 10-K filings. ThemeScope reads them — and shows its work, sentence by sentence.

Built on the ExposureIQ research pipeline. ThemeScope is the conversational, auditable system that grew out of ExposureIQ — the same multi-agent classifier and evaluation discipline, wrapped in a query agent you can talk to.

The Problem

Both obvious ways to measure this fail — one too blunt to catch the signal, the other too unstable to defend.

Keyword counting The classical approach can't tell aspiration from execution, and can't tell an executive taking responsibility from one using the very same vocabulary to avoid it. The words match; the meaning is opposite.
Asking an LLM to "score this 0–100" Fails worse. The number is unstable across a universe, drifts silently the moment you upgrade the model, and — fatally for anyone defending it to an investment committee or a regulator — cannot be audited. You can't point at a portfolio and say the model felt that way.

ThemeScope is built on the single constraint that fixes both.

The language model is a reader and a classifier. It is never a scorer.

Agents read text and emit labels with their reasoning; the score is deterministic arithmetic over those labels, and nothing else. That one separation turns a black box into a research instrument — the output becomes reproducible, point-in-time, backtestable, auditable to the sentence, and safe to upgrade the model underneath.

Enforced as three laws

Not a guideline — three rules the system obeys in code, not in a prompt.

  1. 1

    The model classifies and orchestrates; it never emits a number that reaches the output.

  2. 2

    Scoring is offline and append-only — a prompt or model change writes new rows under a new config hash, it never overwrites an old score.

  3. 3

    Provenance rides on every row, and unverified data is excluded from every cross-sectional statistic.

How it works

Two halves. Scoring runs offline and builds the panel once; querying runs live and only ever reads it.

Offline — build the panel

10-Ks / transcripts → gate → classifier → aggregator → append-only panel

The classifier is the ExposureIQ multi-agent blackboard. Its labels feed a deterministic aggregator, and every score lands in an append-only panel tagged with its config hash and provenance.

Online — the query agent

An analyst asks in plain English; a bounded LangGraph state machine answers.

1
Plan Turn the question into a sequence of tool calls.
|
2
Execute A free heuristic router sends simple lookups straight through and multi-hop questions into a loop.
|
3
Re-plan Execute ⇆ replan, capped at 3 rounds and 12 calls, so chaining never runs unbounded.
|
4
Analyst Assemble the answer from what the tools actually returned.
|
5
Critic Deterministic Python, not a prompt: every number must trace to a tool result, or the response fails.

Auditable to the sentence

Every number in an answer walks all the way back down:

score → firm-quarter → segment → speaker → quote → agent reasoning

Two themes, two different designs

The two themes were chosen because they need genuinely different multi-agent designs — that was the point.

Corporate Integrity AI Disruption
Axis Conduct — how management behaves under pressure Exposure — what the firm is actually involved in
Source Unscripted Q&A of earnings calls Earnings calls (for now)
Agent design Blackboard — four agents observe, then read each other and vote Opposing agents — a line counts only if it survives both a Positive and a Skeptic
Aggregation Share of relevant segments carrying each component Same as Corporate Integrity (for now)

What makes it more than a RAG demo

The say–do gap. The two axes are worth more multiplied than added. A company with heavy AI exposure and a deteriorating accountability trajectory is a specific, nameable thing — narrative without ownership. No single-axis system can see it.
Ambiguity is an output, not an error. When the agents can't agree, the system records a forced label, aggregates a forced rate, greys out those points on every chart, and routes the passages to a human queue.
Provenance that propagates. Drop a transcript it has never seen and the whole pipeline fires live — but that score is written permanently tagged unverified, excluded from every cross-sectional statistic, and physically quarantined in a separate database until a human signs off.

In action

Since the code is private, this is the proof — the question, the tools the agent actually called, and the grounded answer it returned.

"Which industrials show declining accountability — and for the worst one, when did the slide start and what were they saying?"
screen → industrials trending down on accountability
changepoint(ARMK) → the quarter its decline begins
evidence_search(ARMK) → the passages from that quarter
grounded Chained across three planning rounds — the agent isolated the steepest decliner, pinned the quarter the slide began, and pulled the passages behind it. Not "accountability is down," but which company, since when, and in whose words.
"What fraction of INBK's 2024 Q1 relevant segments were about accountability?"
firm_quarter_facts(INBK, 2024 Q1) → 5 accountability of 7 relevant
compute(ratio, 5, 7) → 0.71
grounded 0.71 — the model chose the operation; Python did the division. compute refuses any operand not already returned by an earlier tool, so no hallucinated figure can slip into a number you'd defend to an investment committee.
"Did NKE's integrity profile shift after its CEO change?"
resolve_event_date(NKE, CEO change) → 2024-09-19, from two independent sources
event_delta(NKE, 2024-09-19) → −0.033 across the window
grounded The model resolved only the date from the web; the before/after delta came entirely from the precomputed panel — and the tool enforces event_date ≤ as_of, so the study can't peek at the future.
An early cut — more to come. The query interface is still gaining layers and richer insight types, and ExposureIQ and ThemeScope may eventually fold into a single system.

Engineering decisions

With the repo private, the choices are the tell — each of these took a plainer option over the obvious one, on purpose.

ThreadPoolExecutor for the blackboard, not LangGraph. The blackboard is a fixed fan-out / fan-in over four agents with no dynamic routing — a graph framework would add ceremony and no expressive power. LangGraph earns its place in the query agent, which genuinely branches and loops.
A bounded re-planning loop, not full ReAct. A single-shot planner turned layered questions into advice. The fix is an execute⇆replan loop, capped at 3 rounds and 12 calls with a dedup guard, plus a free heuristic router that skips re-planning entirely for simple lookups — chaining without surrendering determinism or bounded cost.
Opposing agents in sequence, not parallel. The Skeptic only runs on lines the Positive agent passed, and short-circuits; a free keyword prefilter runs before either. Parallel would have been simpler and roughly twice the cost for no gain.
Prompts are immutable, versioned code. A merged prompt is never edited — you add a version and bump a registry pin. Combined with a config hash on every score row, you can always answer which exact prompt produced this number?

Deliberately left out: Kafka, Celery, Postgres, Neo4j, a separate vector service. A JobRunner interface marks exactly where a queue would slot in if scale ever demanded one.

Non-goals: not a trading system — no portfolio optimisation, market data, investment advice, or fine-tuning.

Most systems in this space ask you to trust a number. ThemeScope asks you to check one.
